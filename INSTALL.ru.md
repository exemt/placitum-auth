# Установка

[English](INSTALL.md) · Русский

Один образ, два контейнера: инспектор на шине и HTTP-форма входа. Обычно их ставит
`placitum-core`; здесь — что им нужно, какими переменными это называется и какие маршруты nginx
обязаны быть.

```sh
docker build -f deploy/Dockerfile -t placitum/auth .
```

В образе `auth`, `auth-http`, `auth-probe`, страница входа `web/` и один выключенный профиль
`default`. Настоящие профили присылает контроллер поколением; до этого проверка входа объявлена и молчит.

| Сервис | Команда | Роль |
| --- | --- | --- |
| `inspector-auth` | `auth` | подписка на `waf.req.auth`, вердикт примерно за 20 мс |
| `auth-http` | `auth-http` | форма входа, цель `waf_redirect_allow` |

Масштабируются независимо: инспектор растёт с RPS маршрута, форма — с числом входов.

## Настройки

| Переменная | Кто читает | По умолчанию | Что задаёт |
| --- | --- | --- | --- |
| `NATS_URL` | оба | `nats://127.0.0.1:4222` | шина; форме нужна только под `list.sessions` |
| `WAF_AUTH_SUBJECT` | инспектор | `waf.req.auth` | подписка |
| `WAF_AUTH_NAME` | оба | `auth` | имя в реестре инспекторов |
| `WAF_AUTH_PROFILES` | оба | `./profiles`; в образе `/app/profiles` | стартовые профили |
| `WAF_AUTH_DATA` | оба | пусто; в образе `/var/lib/waf/auth` | применённое поколение от контроллера; пусто — только стартовые профили |
| `WAF_AUTH_KEY_FILE` | оба | — | обязателен: ключ, которым запечатаны сессии и билеты формы |
| `WAF_AUTH_APP_KEY_FILE` | форма | пусто | ключ удостоверения приложения; без него `waf_id` не выдаётся |
| `WAF_AUTH_HTTP_URL` | инспектор | пусто | адрес процесса формы |
| `WAF_AUTH_LISTEN` | форма | `:8080` | адрес формы |
| `WAF_AUTH_WEB` | форма | `./web`; в образе `/app/web` | каталог шаблона страницы |
| `WAF_AUTH_CONTROLLER` | форма | пусто | адрес контроллера: у него забирают конверты объектов хранилища |
| `WAF_AUTH_SCOPE` | форма | пусто | UUID пространства либо `name:<имя>` |
| `WAF_AUTH_CONTOUR_KEY` | форма | пусто | приватный ключ установки: им открываются ссылки `store:` |
| `WAF_AUTH_COOKIE_SECURE` | форма | `on` | куки только по TLS; пока узел отвечает по HTTP, ставьте `off` |
| `WAF_AUTH_REAL_IP_HEADER` | форма | `X-Forwarded-For` | заголовок с адресом клиента; берётся последнее значение — его дописал узел |
| `WAF_AUTH_VERIFY_LIMIT` | форма | число ядер, не меньше 2 | одновременных проверок пароля; отправка, которая ждёт очереди дольше 5 с, отклоняется |
| `REDIS_URL` | инспектор | `url` из `inspector.conf` | буфер: заголовки запроса с кукой сессии |
| `REDIS_INTERNAL_URL` | форма | `internal` из `inspector.conf` | внутренний Redis под nonce, попытки и зеркало сессий; без него — `REDIS_URL` с предупреждением |
| `WAF_AUTH_GEO_ADDR` | инспектор | пусто | справочник сетей (`host:port`) для записей в наборы с `write: net` / `net_all` / `asn`; пусто — такие записи отвечают `AUTH_GEO_UNAVAILABLE` |
| `WAF_AUTH_GEO_TIMEOUT`, `WAF_AUTH_GEO_NEG_MAX` | инспектор | `500ms`, `0` | ожидание справочника сетей на промахе и предел отрицательного кэша |
| `WAF_AUTH_STORE_TIMEOUT` | инспектор | `150ms` | таймаут чтения из буфера |
| `WAF_AUTH_WORKERS`, `WAF_AUTH_QUEUE_DEPTH`, `WAF_AUTH_QUEUE_FULL`, `WAF_AUTH_QUEUE_EXPAND` | инспектор | число ядер, `inspector.conf` | воркеры и очередь |
| `WAF_AUTH_VERSIONS` | инспектор | `2` | принимаемые версии схемы сообщения |
| `WAF_AUTH_LOG` | оба | `info` | уровень журнала |

Пароль служебной учётки LDAP берётся либо из объекта хранилища (`password_store`), либо из
переменной окружения, названной в профиле (`password_env`).

## Ключи

Ключей два, и это не дублирование. Ключом установки запечатаны сессия и билет формы — его знают
только инспектор и форма. Ключом приложения запечатано удостоверение `waf_id` — его знает ещё и
защищаемое приложение. На старте ключи не генерируются: две реплики выписали бы несовместимые
токены. Нет файла — процесс не поднимается.

```sh
openssl rand -hex 32 > secrets/auth.hmac
openssl rand -hex 32 > secrets/auth-app.hmac
```

## Маршруты nginx

```nginx
waf_inspector auth subject=waf.req.auth;
waf_deny_response auth_required status=401;
waf_redirect_allow /waf/login;

server {
    location / {
        waf_capture request headers;
        waf_inspect request auth wave=2 timeout=20ms;
        proxy_pass http://app;
    }

    location /waf/login {
        proxy_pass http://auth_http;
    }
}
```

Путь формы обязан совпасть с `login.uri` профиля и войти в `waf_redirect_allow`. На собственном
`login.uri` проверка входа отвечает `allow`, так что `location` формы может сохранить инспекторов сервера.
Если контейнер формы пересоздают чаще, чем перечитывают конфигурацию nginx, адресуйте его через
переменную и `resolver`, а не блоком `upstream`.

## Проверка

В образе есть `HEALTHCHECK`: `auth-probe` публикует проверку и ждёт вердикт. Для `auth-http` его
переопределяют HTTP-проверкой формы.

## Типичные ошибки

- **`WAF_AUTH_COOKIE_SECURE` по умолчанию `on`.** За чистым HTTP браузер куку не вернёт, и каждый
  вход заканчивается снова на форме.
- **Аварийный выход.** Если вход сломался, уберите `auth` из `waf_inspect` маршрута: невыбранный
  инспектор не опрашивается, и редиректов не возникает.
