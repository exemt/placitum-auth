# Установка

Один образ, два контейнера: инспектор на шине и HTTP-форма входа. Обычно их поднимает
фундамент установки (`placitum-core`); здесь — что им нужно, какими переменными это называется
и какие маршруты nginx обязаны быть.

| Файл | Что делает |
| --- | --- |
| [`Dockerfile`](deploy/Dockerfile) | Собирает `auth`, `auth-http` и `auth-probe`, кладёт `web/` и один выключенный профиль `default` |

```sh
docker build -f deploy/Dockerfile -t placitum/auth .
```

Сервисы в compose установки:

| Сервис | Команда | Роль |
| --- | --- | --- |
| `inspector-auth` | `auth` | Подписка на `waf.req.auth`, вердикт за 20 мс |
| `auth-http` | `auth-http` | Форма входа за `waf off`, цель `waf_redirect_allow` |
| `ldap` | образ `osixia/openldap` | Каталог стенда для провайдера `ldap`; не часть продукта |

Масштабируются независимо: инспектор растёт с RPS маршрута, HTTP — с числом
входов. Секрет один на оба, из него выводится ключ подписи сессии.

## Переменные

| Переменная | Кто читает | Значение |
| --- | --- | --- |
| `NATS_URL` | инспектор | Шина |
| `WAF_AUTH_SUBJECT` | инспектор | `waf.req.auth` |
| `WAF_AUTH_NAME` | инспектор | Имя в реестре nginx |
| `WAF_AUTH_PROFILES` | оба | Каталог bootstrap-профилей. В образе — один выключенный `default`; настоящие профили присылает контроллер поколением |
| `WAF_AUTH_KEY_FILE` | оба | Файл с ключом контура; обязателен |
| `WAF_AUTH_APP_KEY_FILE` | HTTP | Ключ удостоверения для приложения; без него `waf_id` не выдаётся |
| `WAF_AUTH_DATA` | оба | Каталог применённого поколения из KV; пусто — только bootstrap-профили |
| `WAF_AUTH_CONTROLLER` | HTTP | Адрес контроллера: у него забирают конверты store-объектов |
| `WAF_AUTH_SCOPE` | HTTP | UUID пространства либо `name:<имя>` |
| `WAF_AUTH_CONTOUR_KEY` | HTTP | Приватный ключ контура: им открываются ссылки `store:` |
| `WAF_AUTH_LISTEN` | HTTP | Адрес формы, по умолчанию `:8080` |
| `WAF_AUTH_WEB` | HTTP | Каталог шаблона страницы |
| `REDIS_URL` | инспектор | Обменник модуля: заголовки запроса с cookie сессии по локатору. Перекрывает `url` блока `redis` из `inspector.conf` |
| `REDIS_INTERNAL_URL` | HTTP | Внутренний Redis контура под roster (nonce, отказы, отзыв). Перекрывает `internal` блока `redis` из `inspector.conf`; без обоих — `REDIS_URL` с предупреждением при старте |
| `WAF_AUTH_GEO_ADDR` | инспектор | Кодер гео по gRPC (`host:port`, на стенде `geo:50051`) для записей в наборы с `write: net` / `net_all` / `asn`. Пусто — такие записи отвечают `error` (`AUTH_GEO_UNAVAILABLE`), адрес пишется как обычно |
| `WAF_AUTH_GEO_TIMEOUT` | инспектор | Сколько ждать кодер на промахе, в бюджете сообщения; по умолчанию `500ms` ([замер](https://github.com/exemt/placitum-geo/blob/develop/docs/README.md)) |
| `WAF_AUTH_GEO_NEG_MAX` | инспектор | Потолок отрицательного кэша кодера; `0` — умолчание (миллион записей) |
| `WAF_AUTH_LDAP_PASSWORD` | HTTP | Пароль служебной учётной записи LDAP |
| `WAF_AUTH_COOKIE_SECURE` | HTTP | `off` на стенде без TLS; иначе cookie не вернётся |
| `WAF_AUTH_REAL_IP_HEADER` | HTTP | Заголовок с адресом клиента, по умолчанию `X-Forwarded-For`. Берётся последнее значение — его дописал узел; начало списка пишет клиент. На нём держатся привязка сессии к подсети и счётчик попыток по адресу |

Связь с шиной HTTP-процессу нужна только под активный список: профиль без
`list.sessions` к NATS не ходит вовсе.

Ключ не генерируется на старте: две реплики выписали бы несовместимые токены.
Нет файла — процесс не поднимается.

Ключей два, и это не дублирование. Ключом контура запечатаны сессия и билет
формы — его знают только инспектор и форма. Ключом приложения запечатано
удостоверение `waf_id` — его знает ещё и защищаемое приложение. Отдать
приложению ключ контура нельзя: с ним оно выпишет себе вход мимо второго
фактора.

```sh
openssl rand -hex 32 > secrets/auth.hmac
openssl rand -hex 32 > secrets/auth-app.hmac
```

## Маршруты nginx

```nginx
location /waf/login {
    waf off;
    proxy_pass http://auth_http;
}
```

`waf off` обязателен и проверяется при `nginx -t`: иначе вход требует входа.
Путь обязан совпасть с `login.uri` профиля и войти в `waf_redirect_allow`.

На стенде адрес формы задан переменной и `resolver`, а не блоком `upstream`:

```nginx
set $app_auth auth-http:8080;
proxy_pass http://$app_auth$request_uri;
```

Блок `upstream` резолвит имя один раз при загрузке конфигурации и держит адрес
до `reload`, а контейнер формы пересоздают чаще, чем перечитывают конфиг, —
после `docker compose up --force-recreate auth-http` маршрут отвечал бы 502. В
бою, где адрес формы стабилен, обычный `upstream` уместнее.
