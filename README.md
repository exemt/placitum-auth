# Второй фактор

Два контейнера, один образ: инспектор на шине решает `allow` / `redirect` /
`deny`, HTTP проводит вход и выписывает `waf_sid`. Способ входа задаёт профиль —
один провайдер: код, список логинов и паролей, LDAP или NTLM; «пароль плюс
TOTP» — две калитки на маршруте.

Устройство — [docs/README.md](docs/README.md) · установка, два контейнера, ключи и маршруты
nginx — [INSTALL.md](INSTALL.md) · соседи в контуре: инспекторы `captcha` и `counter`.

```
inspectors/auth/
├── cmd/inspector/     шина, waf.req.auth, timeout=20ms
├── cmd/http/          форма входа, выход, продление
├── cmd/probe/         healthcheck инспектора
├── internal/token/    запечатанные токены: сессия, билет, удостоверение
├── internal/decide/   лестница вердикта, чистая функция
├── internal/jwt/      разбор и проверка чужого JWT (провайдер jwt), stdlib
├── internal/learn/    подглядывание входа приложения (провайдер app), чисто
├── internal/roster/   nonce, попытки, отзыв: Redis или память
├── internal/provider/ local, code (TOTP), ldap, ntlm
├── internal/otp/      TOTP по RFC 6238: общий у провайдера и пробы
├── internal/store/    заголовки из обменника по локатору
├── internal/config/   окружение, inspector.conf, профили
├── web/               страница входа без JS
└── deploy/
```

Профилей в репозитории нет: их доставляет контроллер поколением, а образ поднимается с одним
выключенным профилем `default` — подсистема объявлена и молчит до первого поколения.

## Быстрая проверка

```sh
docker build -f deploy/Dockerfile -t placitum/auth .
docker buildx build -f deploy/Dockerfile -t placitum/auth "https://github.com/exemt/placitum-auth.git#develop"
```

На стенде платформы — сервисы `inspector-auth`, `auth-http` и каталог `ldap`. Демо-профили,
маршруты и прогоны (`tests/auth`) живут там же, в платформе.

## Что тут важно помнить

- **Cookie на `allow` модуль не ставит.** Скользящей сессии нет; продление —
  это редирект на `<login>/renew`.
- **`headers.unset` на фазе запроса не работает.** Заголовки личности
  выставляются на каждом `allow` целиком, включая пустые: только так
  перезаписывается подделанный клиентом `X-WAF-User`.
- **Маршрут обязан снимать заголовки и не маскировать `cookie`** — иначе
  инспектор видит sha256 вместо токена и уводит на форму вошедших.
- **`waf off` на `location` формы обязателен**, иначе вход требует входа.
- **Один профиль — один `provider`.** Комбинации собираются набором
  инспекторов маршрута; стыкованный TOTP берёт личность из сессии первой
  калитки (`identity.from`), cookie у него с суффиксом имени, список ведёт он.
- **Токены запечатаны, а не подписаны.** Логин и группы не видны ни клиенту,
  ни в логе прокси. Приложению личность едет отдельной cookie `waf_id` под
  своим ключом.
- **Механизм один: кука и список.** Подпись куки доказывает, что сессию
  выписали мы; запись в активном списке — что её не завершили. Инспектора
  спрашивают на каждом запросе, он сверяет `sid` со своим зеркалом набора
  (`internal/livelist`), и удаление записи из списка — единственный способ
  завершить сессию снаружи. Свежая сессия проходит по одной подписи
  (`list.grace`, 15с): запись едет через секвенсор контроллера.
- **В активный список едет `sid`, а не сама кука** — по расчёту: токен сотни
  байт, `sid` тридцать два знака. Reason записи несёт логин — список в панели
  читается как список вошедших.

## Ветки

`develop` — то, что разрабатывается: сюда приезжает каждая выкладка. `main` — выкаченные сборки.
Правок в этом репозитории не делают: обе ветки производные от платформы.
